# AGAP — Automated Guidance and Emergency Prioritization
Sinalhan Elementary School · Barangay Sinalhan · CDRRMO

A single Node service that hosts the API **and** the installable PWA.
Four roles share one live data store, so a report from a teacher appears on the
Principal, Parent/PTA and Barangay/CDRRMO devices within about a second.

| Role | What they do |
|---|---|
| Teacher | 3-tap report (sent immediately; "Cancel this alert" on the last-report panel undoes a mistake), edit own profile/room, personal history |
| Principal | Command queue, can also report, official History (permanent delete), teacher roster, weights/escalation matrix |
| Parent/PTA | Sees only alerts for their child's section (plus whole-school alerts); "All clear" when closed; past advisories |
| Brgy. Sinalhan / CDRRMO | Priority dispatch queue: Acknowledge → On-Site → Resolve / False alarm; History |

## Run locally
```bash
npm install
npm test                 # 17 API tests (roles, scoping, merging, offline replay, SSE…)
npm run dev:all          # starts BOTH the API (:3000) and the app (:5173) in one terminal
# (or separately: npm run dev:server  and  npm run dev -- --host)
# or production-style:
npm run build && npm start   # http://localhost:3000
```

## Deploy on Render
1. Push this folder to GitHub.
2. Render → **New + → Blueprint** → select the repo (uses `render.yaml`).
3. (Recommended) In the service's Environment tab set `AGAP_ACCESS_CODE` so strangers with the URL can't pick "Principal".
4. Open the `https://<name>.onrender.com` URL on an Android phone in Chrome → **Install app**.

After your first local `npm install`, commit the generated `package-lock.json`, then you may change the build command to `npm ci --include=dev && npm run build`.

### Free vs paid (important for an emergency tool)
* **Free plan**: the service sleeps after ~15 min idle (first request can take about a minute) and the filesystem is wiped on every restart/deploy → incidents and roster edits reset. Fine for demos/defense.
* **Starter + disk** (see comments in `render.yaml`): always on, data persists in `DATA_DIR`. Use this for any real pilot.
* Run **one instance only** — state is held by a single process.

### Environment variables
| Var | Purpose |
|---|---|
| `AGAP_SECRET` | Signs login tokens (auto-generated by the blueprint) |
| `AGAP_ACCESS_CODE` | Optional shared code required at login |
| `DATA_DIR` | Where `agap-db.json` is stored (mount a disk here) |
| `SEED_DEMO_INCIDENT` | `1` adds one sample flood incident at boot |
| `HISTORY_DAYS` | How long closed incidents are kept before auto-removal (default 90) |
| `ALLOW_DEMO_RESET` | `0` hides/disables the Principal's "Reset demo data" |

## What "PWA" means here
Installable (manifest + icons incl. maskable), app shell cached by a service worker so it opens with no signal,
`/api` is never cached, reports made offline are queued on the device and auto-sent (idempotent) when the connection returns,
live updates over Server-Sent Events with polling fallback, browser notifications for new alerts while the app is open/backgrounded.
**Not included:** true push notifications when the app is fully closed (needs Web Push/VAPID keys + a push service) — a good next step.

## History and deleting records
Every resolved, false-alarm or cancelled incident moves to **History** for all four roles, with full details (score breakdown, timeline, who acknowledged/closed).
* **Principal** = the official record. Delete (one, or "Clear history") is **permanent for everyone**.
* **Teacher / Parent / Responder** deletes only remove it from **their own** history; the Principal's record stays.
* Only closed incidents can be deleted. Parent accounts are per section, so clearing history hides it for that section's parent account.
* Reporters can cancel their own alert until a responder is on site, unless other people also reported it.
